# Finished Picture with native game FG - two-route experiment

Branch: `codex/finished-picture-native-fg-unlocked`, based on `34a1504e` (the Superior Scaling review fixes). PR #249 stays on its original branch.

Under `NR Pass at: Finished Picture`, `Native FG integration` selects:

- **Janblade - unblocked** (default, `[DlssNr] FinishedGameFgMode=0`): janblade's existing swapchain presentation path with the shared native-game-FG pause removed. It retains janblade's newest-input-only selection, presentation-epoch window, colour processing and queue-readiness checks. This is the direct unblock comparison; generated presents are not identified by this route.
- **Wilsjo2 - before FG** (`FinishedGameFgMode=1`): ports the original wilsjo2 v59 Streamline application-buffer/render-queue handoff (source commits `9107a2f2` and `42956042`). NR edits the real application frame before the original plugin's Present/Present1 interpolates it. Lower presentation hooks skip that registered chain, preventing a second application on generated frames. While FG is active or its state is uncertain, a plugin-declined application buffer is never replaced by an asynchronous display buffer. As in the source, this route selects the newest ready capture by serial instead of treating generated-present counts as application-frame age.

The game plugin and OptiScaler's local plugin keep separate function pointers. The original local-runtime exception is limited to Kingdom Come: Deliverance II without replacement NGX FG; the native game-plugin route is not limited to KCD2. Wrappers are installed when Streamline requests them, regardless of the selected option, so the menu can switch live. Registration alone does not run NR in the default mode. Changing the option invalidates pending captures/residual history once; slot fences continue protecting in-flight resources. Swapchain buffer/metadata queries for the pre-FG handoff precede the NR lock, preserving the original lock order.

When no compatible application-buffer hooks/render-queue registration exist, the Wilsjo2 option has no pre-FG handoff and falls back to janblade's lower presentation path, as the original integration does. The status `Applying NR before Streamline interpolation (Wilsjo2).` confirms actual full-model handoff execution; selecting the option alone does not prove compatibility. An already created swapchain without registration may require game restart to exercise that handoff.

When a registered Streamline runtime stops exposing application buffers with FG off, its app-facing Present wrapper now composes the ordinary game picture on the saved render queue before calling the original pass-through Present. This uses janblade's existing colour/composition/input-selection path. The persistent registration remains in place, so lower/asynchronous presents cannot apply NR again and FG can restart safely. A valid application buffer always takes priority, including with FG off; that frame is processed only once. Swapchain and colour-space queries still precede the NR lock.

A successful game `slDLSSGSetOptions(Off)` permits this pass-through immediately, even if an evaluate from the last FG frame is still recent. Without an observed options call, the existing mode/recent-evaluate detector is used. Failed options calls are treated conservatively and do not authorize reading the ordinary picture. The new regression first failed on the previous build, then passed with this fix. It covers no-FG startup, explicit Off with recent FG work, repeated Off/On for native/local plugins, GetIndex/GetBuffer declining independently, absent render-queue registration, and all skip/test/disabled/shutdown guards. No per-frame GPU dispatch, texture, copy or allocation is added to the successful application-buffer path; this fixes missing NR work in the off path, not an NR performance optimization.

Both routes reuse janblade's NR/Superior pipeline, SDR/scRGB/HDR10 conversion and residual composition. No NR shader, gain, guide-scaling, private DLSS or exposure algorithm is changed. The original game-FG detector stays intact; only the shared runtime pause decision is overridden. Cross-queue work must be complete before composition; no wait for unfinished input is introduced. Resize still waits only for slots that touched a back buffer, retaining janblade's deadlock protection.

Run `tests/run_nr_finished_fg_tests.ps1` with MSVC installed. Validation includes real D3D12/WARP queue readiness and device removal, both slot-selection policies, resize waits, application-buffer rotation, a pre-FG edit surviving the FG output copy, separate native/local plugin buffers, registration on the render queue, A/B switching, skip/test/disabled/shutdown guards, PQ/10-bit metadata, and existing SDR/scRGB/HDR10 colour/residual regression. The wrapper harness compiles the production implementation with only application includes replaced by test seams.

In-game validation is still required for Crimson Desert and each native Streamline version: compare the two options with identical NR settings, including camera/object motion, HUD, loading, FG toggle, HDR and resolution changes. Tests do not execute the actual proprietary frame-generation model, establish real-frame guide alignment in every game, or measure in-game GPU cost. No performance gain or production compatibility is claimed from WARP.
